# Agent map: one graph of every agent and its subagents

## Goal

Under the search box of the «Агенти» page the column showed «Активні агенти поза цим вибором:
Platinum OS - BE, BE.» — a list of project names that tells the operator nothing they can act
on. Replace it with a «Карта агентів» button that opens, in place of the chat pane, a graph of
every agent on this machine and the subagents each one spawned: a top-down tree in Kermanych's
style, built on the same canvas library n8n uses.

## Context

- The note: `apps/ui/src/pages/AgentsPage.vue:57-60` (template), `:1557-1576`
  (`outsideScopeProjects`, `outsideScopeNote`), i18n `agents.board.outsideScope` /
  `outsideMore` in `i18n/{uk,en}/index.ts`. It lists projects outside the current scope that
  have a session in `ACTIVE_STATUSES`; it ignores the bucket tabs. The same block also holds
  `agents.hints.pickProject`.
- A per-session «Карта агентів» already exists: ◈ in the detail bar (`AgentsPage.vue:189-193`)
  opens a `KModal` (`:1103-1136`, logic `:1240-1303`) with an indented list of
  `store.subagents[sessionId]`; a row drills into the subagent's transcript
  (`api.getSubagentTranscript`, rendered with `KLogBlock`). It is a list, not a graph, and it
  covers one session.
- Two parent/child relations exist in the data:
  - **session → session**: `Session.parentSessionId`, set for `kind: "discussion"` and
    `kind: "review"` forks (`supervisor.service.ts` `branchSession`, `reviewSession`); one
    level, persisted in SQLite.
  - **session → subagent → nested subagent**: `SubagentNode` (`packages/core/src/types.ts:314`),
    `parentId` derived from a dotted id (`Parent.Child`). Held in API memory on the session's
    `Live` (`supervisor.service.ts:135-141`), merged from the runtime registry and the `task`
    tool details, fanned out as `subagents_update`. Survives the idle reaper (the `Live`
    stays), lost on «Завершити», delete and API restart. **Not part of the socket `snapshot`**
    (`supervisor.snapshot()` = projects + sessions), so after a UI reload the store has no
    trees until a new subagent frame arrives — the ◈ button also stays hidden meanwhile.
    Native sessions report no subagents.
- Scope: `selectedProjectId` / `selectedWorkspaceId` in `useOrchestrator`; `inScope` =
  `sessionScopedProjectIds()` (`lib/scope.ts:120-131`). Buckets: `lib/buckets.ts`.
- UI stack: Vue 3.5, Quasar 2, Pinia; no graph library in the workspace. Theme tokens in
  `packages/tokens/src/tokens.css` (dark default, `light`, `matrix`). Workspace colour:
  `projects.workspaceById.get(id)?.color`, fallback `var(--k-accent)` (as `ManagementPage.vue:539`).
- UI tests are pure unit tests over `lib/*.ts` (no component mounting).

## Decisions

1. **The map covers the whole machine**, not the current selection: workspaces → projects →
   sessions → forks → subagents → nested subagents, regardless of the sidebar choice. On open
   the viewport is fitted to the current selection (the selected project's or workspace's
   subtree); from ◈ it is fitted to that session. Rejected: only the current selection — it
   loses exactly what the old note was about (agents elsewhere); only one session — that is
   the existing modal redrawn, and it does not answer «what is running right now».
2. **Which sessions: chips above the map**, «Активні» / «Очікують» / «Помилки» / «Завершені»,
   the same bucket meanings as the sidebar (`lib/buckets.ts`, a fork follows its parent's
   bucket). Default: the first three on, «Завершені» off. The choice is kept in
   `localStorage` (`kermanych.agents.map.buckets`). Chat sessions (`kind: "chat"`) and backlog
   cards are never on the map — no agent stands behind them. Rejected: active only (a session
   waiting for the operator disappears); following the sidebar bucket (confusing on a
   machine-wide map); everything always (160 finished sessions bury the live ones).
3. **Where: in place of the right pane (`agents__detail`).** The session list stays on the
   left. The open/closed state is not persisted; a reload shows the usual screen. Rejected: the
   whole content area, a `/map` route, a full-screen modal — all detach the map from the list
   or cover the rest of the UI.
4. **Clicks.**
   - A session node selects the session and returns the right pane to its chat (the map
     closes).
   - A subagent node opens a drawer on the right side *inside the map* with its transcript
     (`api.getSubagentTranscript`, `KLogBlock`, the existing skeleton/empty/410 handling) and
     its metrics; the map stays.
   - A card in the left list, while the map is open, closes the map and opens that chat —
     the list always means «go to this agent».
   - Project and workspace nodes only collapse/expand (decision 9); they navigate nowhere.
   Rejected: inspector-first (one extra click for the most frequent action); list click
   centring the node (the list would act two different ways).
5. **The ◈ modal is removed; ◈ stays** and opens the new map fitted to this session with its
   node highlighted. Shown, as now, when the session has subagents. The name stays «Карта
   агентів» (`agents.map.*`) — one term in the UI and the README. Rejected: keeping both (two
   different «Карта агентів»); removing ◈ (loses the contextual entry).
6. **Subagent trees join the socket snapshot.** `supervisor.snapshot()` adds
   `subagents: Record<sessionId, SubagentNode[]>` for every session with a `Live` and a
   non-empty tree; the store's `snapshot` reducer replaces `subagents` with it. The map is
   complete after a UI reload; this also fixes the hidden-◈-after-reload bug. Trees stay
   in memory only: after an API restart old sessions show no subagents. Rejected: persisting
   trees in SQLite (migration, constant writes, and a subagent whose transcript cannot be
   opened until the session is resumed — a separate task if ever needed); per-session
   `GET /subagents` on open (N requests, same loss on restart).
7. **Rendering: `@vue-flow/core`** (MIT, peer `vue ^3.3`; n8n's canvas `WorkflowCanvas.vue`
   is built on it): pan, wheel/pinch zoom, fit view, minimap, custom Vue node components,
   animated edges. **Layout is ours**: a pure function in `apps/ui/src/lib/agentMap.ts` that
   builds the tree and assigns top-down positions (the structure is always a forest, so no
   dagre). Node styles use Kermanych tokens only, so dark / light / matrix themes work as they
   are. Rejected: hand-written SVG + own pan/zoom (more code to own for one dependency less);
   adding `@dagrejs/dagre` (not needed for a tree).
8. **One tree, every level a node.** Workspace → project → session → fork → subagent → nested
   subagent, top to bottom. Two edge kinds: thin dashed «belongs to» (workspace → project →
   session) and solid «spawned» (session → fork / subagent, subagent → nested subagent). Every
   edge on the path down to a running agent is animated in the accent colour, so a busy branch
   reads from the top. Empty branches are not drawn: a project with no
   session under the chosen chips is absent, a workspace with no such project too. A session
   whose project has no cloud row hangs under a «Без воркспейсу» root, and an unknown project
   reads as the existing `agents.board.unknownProject`. Rejected: workspace/project frames
   (nested group layout, no longer the tree of the brief); projects as roots without the
   workspace level.
   Node content:
   - **workspace / project**: workspace-colour dot, name, count of active sessions;
   - **session**: `KStatusDot`, name, the board card's status line (tool / todo / status
     word), harness and «аналіз» marks, model, tokens · cost, open findings count; an active
     session has an accent border with a pulse, the selected session is highlighted;
   - **subagent**: status, `description` (fallback `id`), agent type, model, duration, tokens —
     the fields today's `mapMeta` shows.
9. **Collapsing.** Every node with children has a ▸/▾ toggle with a hidden-count badge
   («▸ +12»). Default: workspaces and projects always open (folding them would turn a chip of
   waiting agents into a row of bare project names); a session or subagent is open when its
   subtree holds an active agent (session status in `ACTIVE_STATUSES` or subagent `running`),
   folded otherwise. Clicking a workspace or project card toggles it too. A manual toggle lasts
   for the UI session (module state keyed by node id, survives closing and reopening the map),
   not in `localStorage`; a focus (decision 1) unfolds the target's ancestors. Rejected: always
   expanded (parallel fan-outs make the map unreadable); persisted collapse (stale for finished
   sessions, keys that need cleaning).
10. **The button.** The note and its code (`outsideScopeProjects`, `outsideScopeNote`,
    `outsideScope` / `outsideMore` in both locales) are removed. In their place, under the
    search, a full-width button: «◈ Карта агентів» on the left, «N активних» on the right
    (mono, muted; machine-wide count of sessions in `ACTIVE_STATUSES`, chats excluded). Always
    visible; pressed (accent border) while the map is open; a second click returns to the
    chat. `agents.hints.pickProject` stays where it is. Rejected: no counter (loses the one
    useful part of the old note); an icon next to the search (easy to miss in a 340 px column).

### Behaviour details

- **Live updates.** The graph is derived from `store.sessions`, `store.subagents` and the
  cloud project/workspace lists, so `session_update` / `subagents_update` re-render it.
  Positions are recomputed, but the viewport is fitted only once, when the map opens; later
  updates never move the operator's pan/zoom.
- **Opening fit.** The focus is fitted with a zoom floor of 0.7, so a project with a dozen
  agents side by side opens readable and centred rather than as a strip of specks; the rest is
  a pan away and on the minimap. The ⤢ «Вписати все» control fits everything at any zoom.
  Wheel / two-finger scroll pans (as in n8n); pinch, ⌘-wheel (Ctrl-wheel off macOS) and the
  «+» / «−» buttons zoom.
- **Chips** show the machine-wide count of each bucket next to its name.
- **Leaving the map.** Any session selection — a map card, a list card (even the one already
  selected), a notification, the parent ↑ — closes the map and shows that chat. While the map
  is open the chat's ⌘-shortcuts are off: ⌘⌫ must not delete a session that is not on screen.
- **Esc** closes the subagent drawer first, then the map; not while typing or while a modal is
  open.
- **Empty map** (nothing under the chosen chips): a muted line in the map, e.g. «Немає агентів
  під вибраними фільтрами.»; no skeleton once the socket snapshot is in. Before the snapshot:
  `KSkeleton`, per the Async-states rule.
- **No session selected** and the map closed: the existing `agents.detail.blank`. The button
  works without a selected session.
- **Blank page state** (no project and no workspace selected, `AgentsPage.vue:4-7`): the board
  column is not rendered, so the button is not either; unchanged.

## Changes

- **Core** `packages/core/src/types.ts`: `ServerEvent` `snapshot` gains
  `subagents: Record<string, SubagentNode[]>`.
- **API** `supervisor/supervisor.service.ts`: `snapshot()` includes the live trees
  (`subagentList`). `ws/events.gateway.ts` unchanged (it already sends `snapshot()`). The
  one-shot `GET /sessions/:id/subagents` (`SessionsController.subagents`,
  `SupervisorService.getSubagents`) is removed — its only caller was the ◈ modal priming the
  store, which the snapshot now does.
- **UI**
  - `package.json`: `@vue-flow/core`, `@vue-flow/background`, `@vue-flow/minimap`.
  - `lib/agentMap.ts`: build the tree from sessions / subagents / projects / workspaces,
    bucket filter, default collapse, hidden counts, top-down layout, focus helpers, the
    button's active count.
  - `components/agents/AgentMap.vue`: the canvas with its four node templates, chips, zoom
    controls, minimap, subagent drawer.
  - `pages/AgentsPage.vue`: remove the note and the ◈ modal with its logic; the button; swap
    `agents__detail` content to the map; ◈ opens the map focused on the session; list click
    closes the map; `cardLine` shared by the board card and the map.
  - `stores/orchestrator.ts`: the snapshot reducer takes `subagents`; `loadSubagents` and
    `api.getSubagents` removed.
  - `i18n/{uk,en}`: drop `outsideScope`, `outsideMore`, `map.close`, `map.back`; `map.empty`
    now speaks about the filters; add the button, counter, chips, controls, fold, drawer and
    «Без воркспейсу» strings.
- **Tests**
  - `apps/ui/test/agent-map.spec.ts`: tree building (fork under parent, nested subagent under
    its parent, sessions grouped by project and workspace, «Без воркспейсу»), chip filter
    (fork follows parent bucket, chats/backlog excluded), empty branches pruned, default
    collapse and hidden counts, layout invariants (children below the parent, no two nodes
    overlap on one level).
  - `apps/api/test/supervisor.subagents.spec.ts`: the snapshot carries a live session's tree
    (non-empty trees only); the removed `getSubagents` endpoint's tests go with it.
